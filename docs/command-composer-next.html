Implementation notes

The three slices now share the action cards, choice list, keyboard handling, and review state.

1

Fold ⌘O into the composer

Make repository opening a composer action. ⌘O lands directly on its picker; ⌘K shows it among all actions.

  • Move recent repository filtering, ~/ and absolute path completion, native folder choice, loading, and errors out of the separate dialog.
  • Open the selected repository immediately and keep the choice in view as arrows move.
  • Remove the old picker once its behavior is covered.
2

Find and open a PR

Start with the list and open behavior already available, including a direct entry from a selected PR.

  • Show PR number, title, author, draft state, and updated time in searchable choice rows.
  • Paginate explicitly; the current list endpoint has pages but no server-side search.
  • Keep opening a review tab direct. Make worktree checkout a separate action with a confirmation step.
3

Add compact PR actions

Bring copy link and comment submission into context menus and the composer, prefilled with the current PR.

  • Use the existing comment and pending-review endpoints.
  • Keep file-level thread resolution next to the thread because its target is highly contextual.
  • Create, approve, request changes, and merge use the provider bridge and report provider errors in the review state.
↗

Shared code shape

Expand the current intent model without turning the composer into another screen full of controls.

  • Action definitions own labels, availability, required operands, preview text, and executor.
  • Pure flow transitions own Back, arrow keys, Enter, and confirmation when required.
  • Choice, text, and review steps remain reusable components; repo and PR data stay subscribed near those steps.
Implementation snapshot. The provider still enforces repository permissions, branch protection, and merge checks. Bitbucket request-changes decisions have no review note.
